FuguVM

FuguVM installs and manages OpenBSD virtual machines under QEMU. It downloads the install set, creates the disk, and answers the installer through the serial console. The result is a machine that accepts SSH. One command does the unattended install, on a host that does not run OpenBSD.

Thus a Makefile can control an install; you do not have to answer the installer manually.

What it does

Unattended install
fuguvm up downloads the release, creates the disk image, controls bsd.rd through the installer, and starts the machine. The command is idempotent: if you run it again, nothing occurs.
Per-project state
The state is adjacent to the code, in an .fuguvmrc file and an .fuguvm/ directory. FuguVM finds them with a search up from the current directory. A project can define several machines, each with its own release, memory, disk, and forwarded ports.
Cached install images
FuguVM keeps the release sets in a cache under ~/.cache/fuguvm/, and a built-in proxy serves them to the guest. Thus the large download occurs one time, not one time for each machine.
Scriptable
fuguvm ssh runs a command in the guest and exits with the status of that command. fuguvm expect controls the serial console with an expect(1) script. Each failure mode has its own exit code — not started, timeout, download failure.
Automatic accelerator choice
FuguVM selects HVF on macOS, KVM on aarch64 Linux, and TCG on other platforms. The --emulate option overrides the choice.

Origin

FuguVM runs the integration tests of OpenHAP on their target platform: tests of pledge(2), unveil(2), rc.d and mdnsd are possible only on OpenBSD. FuguVM does not know about OpenHAP; this repository is its first user.
