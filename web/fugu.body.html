Fugu

Fugu does the tasks that the base system leaves to an OpenBSD-style daemon in Perl. A daemon must go into the background, write a PID file, drop privileges, reap children, and answer signals. It must read its configuration, keep a little state between runs, write files without a window in which a secret is readable, and talk to a local socket. It must log to syslog or to stderr, as applicable to how it started. It must limit itself with pledge and unveil, and advertise over mDNS without a child process. Fugu supplies these functions.

Fugu loads with core Perl. Some modules load an optional CPAN library on use, and fail with a clear message when it is absent; a program that never uses that module never needs the library. OpenHAP uses Fugu; Fugu does not know about OpenHAP.

The modules

Fugu::Daemon
The module forks, calls setsid, redirects the standard descriptors, changes to the root directory, and sets the file creation mask. It also takes the PID file and holds the lock for the life of the process.
Fugu::Privdrop
The module prepares the state directory while the process is still root. It then drops to a specified user and group, reduces the supplementary groups, and makes sure that the process cannot get root again.
Fugu::Process
The module spawns and execs children, and reports a failed exec over a close-on-exec pipe rather than after a sleep. It runs a command and captures its output, stops a child with a grace period before SIGKILL, reaps zombies, and waits for exit.
Fugu::Signal
The module registers handlers for a controlled shutdown, or for a flag that a long loop can poll. Each manager owns its cleanups and its interrupt flag, and puts the previous handlers back.
Fugu::Log
The module gives one interface for syslog, stderr, and silence, with level filters and printf-style formats. Thus a daemon and a CLI tool can use the same code. It holds the process default logger, which library code uses when the caller gives none.
Fugu::Pidfile
The module manages one PID file. Every write takes the lock before it truncates, and acquire holds the lock for the life of the process. It finds stale PIDs with Fugu::Process.
Fugu::Sandbox
The module is a platform abstraction for pledge(2) and unveil(2): the calls are real on OpenBSD and do nothing on other platforms. Thus the callers do not examine the operating system. A method that fails dies; there is no warn-and-continue mode. It also assembles the path inventories that every daemon repeats.
Fugu::Imsg
The module supplies the base-system imsg framing — a fixed native-endian header and a payload — over a connected stream socket. It reads full messages when the socket returns short counts, and carries the peer id that a request and response protocol correlates by.
Fugu::MDNS
The module publishes services through mdnsd(8) with its control protocol directly, not through a mdnsctl child process. The advertisement stays active while the module holds the socket, and the destructor withdraws it.
Fugu::File
The module reads and writes files, atomically where that matters, and sets the mode at the open so that a secret is never readable before it is written. It also builds a directory tree beside its target and publishes it with one rename.
Fugu::Util
The module holds a wall-clock guard around a call that can block, a bounded poll that stops on an interrupt, and a byte count that a person can read.
Fugu::Random
The module gives random bytes from /dev/urandom and random passwords built from them, in an alphabet that survives a shell, a URL and a configuration file with no quoting.
Fugu::Config
The module parses the OpenBSD-style grammar of settings and blocks. It gives the blocks of a type in file order and also addresses each one by name. A line that the grammar does not accept is an error with a file and a line number, never a line that the parser quietly skips.
Fugu::Store
The module is a small JSON state file with typed accessors. It survives a corrupt file, and it writes atomically so that it does not create one.
Fugu::CLI
The module dispatches the subcommands of a command-line tool, parses the global options and each command's own options, and holds the exit codes that every tool shares. Command data goes to stdout and diagnostics to the logger, so a pipeline that reads the tool keeps working.
Fugu::Control
The module is a control socket for a running daemon, in two parts: a server that answers commands from process state, and a client for the tool that asks. A tool that guesses from files on disk reads what the daemon wrote at some earlier time, and it is wrong whenever the two disagree. The socket is mode 0600 from birth, and everything that arrives on it is untrusted: a bad request is an error reply, never a dead daemon.
Fugu::EventLoop
The module is the select loop that a daemon with one process runs. A caller registers descriptors and timers instead of writing a while with a poll interval and an epoch comparison for each periodic job. The select timeout comes from the nearest deadline, and an interrupt flag ends the loop so the shutdown happens in the daemon and not inside a signal handler.
Fugu::MQTT
The module is a subscribing MQTT client for a daemon with one process and one event loop. It never blocks the caller: a tick drains what arrived and returns. The library underneath loads at connect time, so a daemon whose broker is optional still starts without it.
Fugu::JSONSocket
The module is a client for one JSON object for each line over a UNIX socket, with a wall-clock deadline on every read. QEMU speaks this on its machine-protocol and guest-agent sockets.
Fugu::SSH
The module runs a command on another machine and captures its output, and writes a file over SFTP. An interactive session falls back to ssh(1), which is the only thing that gives correct control of a terminal.
Fugu::Proxy
The module is a caching HTTP proxy in three parts: the supervisor and serve loop, the URL-to-file store, and the metadata that makes a cache hit one write. Which URL is worth keeping is a callback, because that answer belongs to the mirror and not to HTTP.

Reference

Each module has a section 3p manual page under its full name — thus man Fugu::Daemon finds the page. The pages are also listed under Fugu in the manuals.

Name

Fugu is the pufferfish, the mascot of OpenBSD.
