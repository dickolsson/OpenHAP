=head1 NAME

App::FuguWeb::Site - the whole build, from the description to the pages

=head1 SYNOPSIS

    use App::FuguWeb::Site;

    my $site = App::FuguWeb::Site->new(
        config => $config,
        out    => 'web/build',
    );

    my $missing = $site->missing_tool;
    die "$missing not found\n" if defined $missing;

    $site->build or die "the build failed\n";
    $site->clean;

=head1 DESCRIPTION

One method renders the site. Each step reports its own failure and stops
the build: a site that is half rendered must not look like a success.

The build reads nothing from the network, writes nothing outside the
output directory, and gives the same bytes for the same checkout.

=head1 METHODS

=head2 new

    App::FuguWeb::Site->new(
        config => $config,      # required
        out    => $dir,         # default: the out_dir setting
        log    => $logger,      # default: Fugu::Log->default
        render => $render,      # default: one over the same description
    )

=head2 config, out, render, staging

The site description, the output directory, the renderers, and the mdoc
staging directory.

=head2 missing_tool

The name of the first renderer that is not installed, or C<undef>. The
caller reports it before the build starts, so an operator learns which
package to install.

=head2 build

Render the whole site:

=over 4

=item 1.

lint every mdoc source;

=item 2.

create the output directory and the staging directory inside it;

=item 3.

copy every mdoc source into the staging directory under its staged name;

=item 4.

copy the base stylesheet and every asset;

=item 5.

render each C<page> block;

=item 6.

render one page for each manual in each group;

=item 7.

remove the staging directory.

=back

The method returns true on success, and C<undef> with a message in the
log otherwise.

The output directory is created on purpose. The recipe that this
replaced got it as a side effect of the staging C<mkdir>, which would
have broken the moment the staging step moved.

=head2 clean

Remove the output directory. The method returns true when the directory
is gone, whether or not it was there to begin with.

=head2 pod_date

The date that every POD page carries: the date of the last commit, and
today when git does not answer. git does not preserve file times, so a
build that read one would give different bytes on every checkout.

=head1 THE STAGING DIRECTORY

C<mandoc> decides between a local link and a link to the manual host by
looking for a file named C<%N.%S> in its working directory. Every mdoc
source is therefore copied into one directory under its
L<App::FuguWeb::Manual/staged_name>, and C<mandoc> runs there.

The directory lives inside the output directory, under F<.man>, and the
build removes it. Staging is a build detail: a published tree that
carried it would serve the mdoc sources beside the pages made from them.

=head1 ASSETS

An asset is any file directly in the source directory that the build
does not render: not a C<*.body.html> fragment, not Markdown, and not a
dot file. F<robots.txt> and F<CNAME> therefore need no entry in the
description, and a F<CLAUDE.md> beside them is not published.

Markdown in the source directory is either a page source, which a
C<page> block names and C<lowdown> renders, or notes for the
maintainers. Neither belongs in the output as it stands.

=head1 THE STYLESHEET

The base stylesheet ships with the tool, at F<share/fuguweb/style.css>,
and L<Fugu::File/share_path> finds it. The C<stylesheet> setting
overrides the search: the search finds the file in a checkout, but not
under the data path of an installed distribution.

A stylesheet that is not found fails the build and names the path. A
site with no stylesheet must not look like a success.
